Script v1.0.0
Tanzu Platform 10+
RabbitMQ 4.x
What This Script Does
  • Connects to the RabbitMQ Management API from your jump host — read-only, no changes to the cluster
  • Runs health checks across 18 categories: cluster state, resources, queues, security, HA, streams, application health, and more
  • Produces a self-contained HTML report with evidence logs and a ZIP for sharing with Broadcom Support
  • No software is installed on the cluster. No SSH. No config changes. No credentials in reports.
Pre-requisites
Jump Host (required)
  • Linux/macOS jump host with network access to the RabbitMQ Management API HTTPS endpoint
  • bash 4+ — script runtime
  • curl — API calls
  • jq — JSON parsing
Jump Host (optional tools)
  • openssl — TLS certificate expiry check
  • zip — ZIP report packaging
  • bosh CLI (authenticated) — BOSH VM inventory
RabbitMQ User Permissions
monitoring Required for most checks (nodes, shovels, federation) administrator Required for user security checks (/api/users)
BOSH Access (optional)
  • BOSH Director IP, client, secret
  • BOSH CA certificate file
  • Deployment name (bosh deployments)
Deployment Steps
1
Copy the script to the jump host
  • Transfer tanzu_rmq_healthcheck.sh to the jump host
scp tanzu_rmq_healthcheck.sh ubuntu@<jumpbox-ip>:/home/ubuntu/rmq/
chmod +x /home/ubuntu/rmq/tanzu_rmq_healthcheck.sh
2
Create the config file — use the setup wizard (recommended)
  • Run once; answers are saved to rmq.conf automatically
bash /home/ubuntu/rmq/tanzu_rmq_healthcheck.sh --init
  • Wizard asks: customer name, cluster URL, RabbitMQ user ID, password, BOSH details (optional)
  • Or copy rmq.conf.sample and fill in manually — 3 required fields:
customer=Acme-Corp
url=https://rmq-host.example.com
username=monitor-user
password=S3cur3P@ss
3
Validate setup (optional — no checks run)
  • Tests connectivity and permissions before the full run
bash /home/ubuntu/rmq/tanzu_rmq_healthcheck.sh --config /home/ubuntu/rmq/rmq.conf --check-config
4
Run the health check 
bash /home/ubuntu/rmq/tanzu_rmq_healthcheck.sh --config /home/ubuntu/rmq/rmq.conf
  • The pre-scan runs first — shows what is and isn't accessible
  • On interactive TTY: choose C (continue), R (re-run after fix), or Q (quit)
  • Typical run: 15–45 seconds
5
Review the report and share the ZIP
  • Report folder: reports/<Customer>_healthcheck_<timestamp>/
  • Open the HTML file in a browser and review before sharing
  • Check queue names and vhost names — they may reveal business domain
  • Share the ZIP with Broadcom Support via the approved support channel
Report Status Reference
PASSMeets the health baseline — no action needed
WARNINGExceeds soft threshold — investigate
CRITICALExceeds hard threshold — act immediately
REVIEWNeeds customer judgment — not a failure
NOT VERIFIEDMissing access or tooling — root cause shown in report
Common Issues
  • HTTP 401 on /api/nodes — Grant monitoring tag to the RabbitMQ user
  • HTTP 401 on /api/users — Grant administrator tag
  • SSL certificate error — TLS cert has expired; renew via Ops Manager. Use --insecure for lab environments only
  • Wrong URL format — Use https://hostname only, no /api/... path. The script will auto-strip paths if pasted
  • ZIP not created — Install zip: apt install zip
Security & Privacy
✗ Passwords or credentials ✗ Message bodies or payloads ✗ Shovel/federation source or destination URIs ✗ Usernames (only counts recorded) ✔ Queue names and vhost names appear in reports — review before sharing
